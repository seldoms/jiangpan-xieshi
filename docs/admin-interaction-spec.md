# 管理端卡片交互说明

## 目标

管理端服务于正在搬运、捕捞、打包和发货的人。页面要让操作者少看文字、少点按钮，按订单顺序快速推进；所有金额动作都落在具体地址订单上。

## 两层卡片

### 批次汇总卡片

进入管理端先看到当前批次：

- 总订单数、总只数和地址数。
- 按公母、规格拆分的待捕捞数量。
- 当前批次是否已截单。
- 进入订单卡片队列的入口。

捕捞工作按这张汇总卡片执行。它不承载单个地址的运费和金额编辑。

### 地址发货卡片

一张卡片对应一个地址订单，按订单号顺序排列。卡片至少显示：

- 订单号、收货人和地址摘要。
- 公母、规格、数量和包装配置。
- 当前阶段：捕捞中、已打包或已发货。
- 运费和最终应付金额；未登记时明确显示“运费待录入”。

## 手势规则

| 当前阶段 | 手势 | 结果 |
| --- | --- | --- |
| 任意阶段 | 上滑 / 下滑 | 切换上一张 / 下一张订单，只改变当前卡片，不改变业务状态 |
| 捕捞中 | 左滑 | 保存打包成功并打开快递费输入层 |
| 已打包 | 左滑 | 打开快递费输入层；提交后直接标记已发货并重算最终应付金额 |
| 已打包 | 右滑 | 撤回到捕捞中，显示撤销提示 |
| 已发货 | 点击卡片 | 查看金额和处理记录；不允许误触改变状态 |

“左滑打包”和“左滑录入快递费”必须通过当前阶段区分：捕捞中左滑先保存打包成功再打开快递费输入，已打包左滑直接打开。取消输入保留已打包状态。快递费输入层只有一个运费金额输入，提供数字键盘、提交和取消；个人和拼团均不要求录入实重，免运费填 0；提交成功即标记已发货。已发货订单可再次打开修改金额，但不能清空快递费。

## 状态推进

```text
捕捞中 → 已打包 → 已发货
   ↑       │
   └───────┘
    右滑撤回捕捞
```

- 左滑是主要推进动作，完成后立即给出轻量反馈和下一张订单提示。
- 右滑是撤销动作，必须有短暂撤销提示，避免操作者以为数据消失。
- 上下滑动永远只切换卡片，不能触发状态变化。
- 删除订单放在卡片详情的次级操作中，不放在滑动主路径上。

## 金额展示

最终金额按地址订单单独计算：

```text
蟹款 + 包装费 + 运费 = 用户最终应付
```

录入或修改运费后，管理端和用户端都显示最新金额。未录入运费时显示预计金额，并明确标记运费待录入。

## 误触保护和现场验证

- 左右滑动需要超过明确距离阈值，短拖动只跟手不提交。
- 状态变更后显示 2–3 秒撤销提示。
- 进入快递费输入前显示该订单号和收货人，避免录错单；提交后立即显示已发货反馈。
- 数字键盘只接受非负金额，保存前展示金额构成。
- 卡片队列支持键盘方向键作为桌面端备用操作，但不增加复杂菜单。
- 必须在手机端、单手操作、手上忙碌和弱网络场景验证，再决定是否开放更激进的手势。


## 2026-09-19 极简交互补充

- 汇总标题、数量保持同行，例如“待捕捞 · 20 只”；移除重复副标题和教学段落。
- 规格展示使用共享图示；规格、套餐排序由长按把手拖动，键盘上下键也可移动，失败恢复并重载。
- 批次页修改截单日期和时间；每日到点自动发布下一个批次。顶栏可切回历史批次继续履约，已选批次不因后台刷新被替换。


## 2026-09-19 完成打包后直接登记运费

- 点击“完成打包”、卡片左滑或键盘左键，先保存已打包状态，成功后立即打开同一发货单的运费窗口。
- 关闭窗口保留已打包状态，稍后可继续登记；提交快递费才标记已发货。
- 状态保存失败时不打开窗口；请求中防止重复推进。按捕捞筛选时，窗口始终绑定刚打包的订单，不跟随列表下一张。
