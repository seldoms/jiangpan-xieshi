# 积分策略建议

## 结论

积分方向可行，但建议定位为“复购和转介绍工具”，不建议一开始做成复杂的通用积分商城。大闸蟹是低频、季节性、价格敏感的商品，积分必须可配置、可控成本，并且只兑换有限的蟹品或优惠。

积分功能应排在真实订单、用户访问、运费和数据库完成之后。没有服务端订单流水和可识别的用户，就无法可靠发放、扣减和追回积分。

## 适合这个项目的收益目标

1. 让用户在下一批蟹上市时回来复购。
2. 鼓励用户把拼团链接分享给真实买家。
3. 让老客户愿意多买一份或带朋友一起买。
4. 用积分兑换蟹品，减少直接现金折扣对利润的冲击。

## 建议的最小规则

### 获取积分

- 以实际订单中的蟹款金额作为积分基数，运费不计入积分。
- 订单完成发货、金额确认后再发放积分，提交草稿和未成团意向不发积分。
- 个人订单按订单归属发放；拼团按每个成员自己的规格和数量发放，不全部记到团长名下。
- 退款、删除或作废订单时，已发积分必须按原流水追回。
- 发放比例由后台配置，例如按“每消费若干元得 1 分”；开发环境使用测试参数，不能把比例写死在前端。

### 使用积分

- 积分只抵扣蟹款或兑换后台配置的蟹品套餐，不抵扣运费。
- 单笔订单最多抵扣蟹款的一定比例，建议先从 10%–20% 试起，避免整单免费。
- 兑换商品必须绑定当前批次、规格和库存；售罄或下架后不能继续兑换。
- 积分有效期建议 12 个月，过期前在用户页面提醒。
- 积分不能提现、转让或兑换现金。

### 拼团积分

- 成员按自己的实际蟹款获得积分，团长不因为收货地址或最终提交自动获得全部积分。
- 如需鼓励团长，可以单独配置一次性“成团奖励”，且必须在团长提交并成功发货后发放。
- 仅查看拼团链接不产生积分；提交 1 只但最终未成团，也不产生积分。

## 积分商城的最小版本

第一版只需要四个页面能力：

- 用户端显示当前积分余额、即将过期积分和积分流水。
- 下单页在“厚礼蟹”附近显示“使用积分”入口，展示本单最多可抵扣金额。
- 积分兑换页只展示少量可兑换蟹品套餐，不做泛商品商城。
- 管理端配置发放比例、抵扣上限、兑换 SKU、有效期，并能查询和人工调整流水。

积分余额必须由流水计算或由带版本的余额表维护，不能只保存一个可随意覆盖的数字。每条流水至少包含用户、来源订单、变动分值、原因、操作者、时间和幂等键。

## 成本控制和反作弊

- 积分发放基于服务端最终订单金额，不能信任前端传入的金额。
- 同一订单只能发放一次积分；重复提交、刷新和重复 webhook 都不能重复发放。
- 取消、退款、删除订单需要反向流水，不能直接修改历史余额。
- 新用户、拼团成员和团长奖励分开配置，避免通过自己创建多个链接刷积分。
- 兑换和抵扣记录必须保留，管理员调整要有原因和权限记录。
- 监控积分成本占蟹款收入的比例；如果超过预设毛利红线，自动降低发放比例或暂停兑换。

## 建议的验证方式

先做一个批次的小范围试验，不直接上线完整商城：

1. 只给已发货订单发积分。
2. 只开放一个低成本蟹品兑换项。
3. 设置较低抵扣上限和明确有效期。
4. 观察一个销售周期内的复购率、转介绍成团率、积分兑换率和积分成本。

重点看四个指标：

- 90 天内复购率是否提升。
- 拼团链接带来的有效成员数是否提升。
- 积分成本占蟹款毛利的比例。
- 积分兑换后客单价和订单数量是否增长。

如果复购和有效拼团没有明显提升，积分商城就不应该继续扩展；如果提升明显，再增加兑换档位和团长奖励。

## 开发顺序

积分不应现在直接塞进前端原型。正确顺序是：

1. 完成用户/下单码访问、订单、拼团成员和真实数据库。
2. 建立积分账户和不可变积分流水。
3. 接入发货后的积分发放和取消追回。
4. 增加用户积分余额、流水和下单抵扣。
5. 最后再做少量蟹品兑换和团长奖励。
