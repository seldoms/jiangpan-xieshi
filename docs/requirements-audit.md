# 原始会议纪要功能审查

## 审查信息

- 需求来源：`智能纪要：大闸蟹自助下单平台功能讨论`，2026-09-18。
- 最近审查：2026-09-20（本轮：术语定版、预设套装直达、发货卡片复制、站内图标与审计）。
- 当前基线：React/Vite 前端 + Fastify API + SQLite 迁移数据库；用户端、管理端和拼团页均已接真实 API。
- 状态含义：`已实现` 表示已有真实 API 和页面闭环；`部分实现` 表示主流程可用但仍有商用缺口；`待实现` 表示当前版本明确后置。

## 用户端和拼团

| 需求 | 状态 | 现状 / 验收证据 | 后续事项 |
| --- | --- | --- | --- |
| 下单码进入个人采购 | 已实现 | `/api/v1/auth/login` 校验下单码并签发 HttpOnly 会话，订单、购物车和复购均按用户隔离 | HTTPS 上线后启用 `SESSION_COOKIE_SECURE` |
| 个人采购或送礼 | 部分实现 | 个人采购走下单码；送礼通过包装选项表达，不单独建账号类型 | 如要统计用途，再增加订单用途字段 |

| 管理员配置套餐 | 已实现 | 套餐模板 CRUD，服务端校验每盒总数必须为 10 只 | 增加配置审计和更清晰的停用提示 |
| 全公 / 全母 / 混合套餐 | 已实现 | 模板 items 支持任意规格组合，种子数据含混合和全母示例 | 用真实运营价格替换测试价格 |
| 礼盒每盒 10 只 | 已实现 | `BOX_CAPACITY=10`，套餐按份数、自定义按盒数核算包装费 | 无 |
| 多地址粘贴下单 | 已实现 | 前端解析一大段姓名、电话、地址和份数，服务端拆成多个 shipment | 完善异常地址人工修正体验 |
| 少于 10 只可强制提交 | 已实现 | 服务端先返回 `BELOW_TEN_NEEDS_CONFIRM`，明确确认后才创建订单 | 无 |
| 购物车草稿 | 已实现 | 服务端 `cart_drafts` 按下单码隔离，选蟹时即可保存无地址草稿，不生单号，提交后删除草稿 | 自定义多地址复购补充每份原始快照 |
| 快速复购 | 部分实现 | 订单页读取服务端配置并回填当前套餐，地址需重新确认 | 自定义模式补齐每份配置快照 |

| 拼团总数按 10 只倍数成团 | 已实现 | 公开视图返回总数、下一档差额和 `canSubmit`；团长提交由服务端校验 | 无 |
| 团长唯一链接和公开查看 | 已实现 | `/groups/:token` 不需要成员登录，显示成员姓名、规格、数量和金额汇总 | 增加链接失效/重置管理 |
| 成员只填姓名、多规格搭配 | 已实现 | 一个成员可一次提交多种公母规格；动态显示总数与蟹款，地址由团长最终提交 | 无 |
| 不足 10 只转拼团 | 已实现 | 选购页及不足 10 只确认弹窗携带当前配置建团，并原子保存发起人采购记录；分享 token 链接 | 无 |
| 团长最终提交后发货 | 已实现 | 只有团长、成团倍数和地址齐备时才生成订单/发货单 | 通知目前为页面提示，未接短信/微信 |
| 结单前后查看金额 | 已实现 | `/amount` 结单前按当前价估算，结单后按订单快照返回 | 无 |
| 发货后查看成员运费 | 已实现 | 仅录入总运费，按订单快照规格标重 × 数量分摊，余数按提交顺序补分 | 增加更直观的成员金额明细 |

## 结论

原始会议纪要中的主流程已经落到真实 API 和数据库：个人下单、购物车、拼团、批次配置、顺序履约、运费登记和用户金额查看均可联调。会话安全、日志、限流已完成，跨域/反代已跑通；当前阻塞正式上线的内容只剩**用户侧事项**（对外域名/HTTPS、正式价格录入、真机回归）；积分商城、通知渠道和通用报表按既定计划后置。
